Claude Code 2.1.302 更新日誌

翻譯自 官方 CHANGELOG

2.1.302

  • 新增 CLAUDE_CODE_AUTO_MODE_MODEL，可指定客戶端 auto mode 分類器（classifier）使用的模型；這不會改變伺服器端 auto mode 的模型
  • 在 /config 新增一列 Idle compaction，可以關閉或重新開啟閒置壓縮；閒置壓縮後顯示的通知現在會告訴你怎麼關掉它
  • 在 /design-sync 和 /design-login 加上通知，告知獨立版 Claude Design（claude.ai/design）將於 2026 年 12 月 14 日停用
  • 修正在對話正在壓縮時停止某一輪（turn）會跳出「Prompt is too long」錯誤的問題
  • 修正在工作階段中途切換到 Vertex 或 Bedrock 後，請求會以「diagnostics: Extra inputs are not permitted」失敗的問題
  • 修正 Read 工具會把任意大小的圖片檔，或命名成圖片的 pipe 或裝置，整個載入記憶體的問題；現在超過 128 MB 的圖片來源會被拒絕
  • 修正當 gateway 用前綴命名 Opus 4 或 4.1（例如 anthropic/claude-opus-4-1）時，/autocompact 和 /effort 會存到錯誤模型的問題
  • 修正工作階段中途新增的工具透過 ToolSearch 或在壓縮後再次載入時，發生 prompt cache 未命中（cache miss）的問題
  • 修正 claude plugin 和其他子指令有時會在佇列中的設定或 config 寫入完成前就先結束，可能導致變更遺失或留下 .tmp 檔的問題
  • 修正當 git 預設使用 reftable ref 格式時，plugin marketplace 每次重新整理都會重新 clone，以及新安裝的 git plugin 版本顯示為「unknown」的問題
  • 修正 PowerShell 工具找不到 plugin bin/ 資料夾內指令，以及當一個找不到結果的搜尋（rg、grep、findstr、git grep）被 pipe 到 Select-Object 或其他格式化 cmdlet 時會報錯的問題
  • 修正桌面版 app 中的 Claude 會叫你去 claude.ai 設定或 /mcp 來授權或重新連線某個 MCP server，但那個選項其實不存在的問題
  • 修正當 Claude 送出空的編輯清單時 artifact 發佈有時會失敗，以及在較新版本的 artifact 擋下更新後 Claude 用錯誤方式重試 artifact 更新的問題
  • 修正大多數 auto mode 分類器攔截的情況下 OpenTelemetry tool_decision 事件缺少 classifier_category，以及當 OTEL_LOGRECORD_ATTRIBUTE_COUNT_LIMIT 偏低時新的 tool_decision 屬性會把 tool_use_id、tool_source 和 tool_parameters 擠掉的問題
  • 修正在長清單中往下移動或摺疊某個區塊後，agents 檢視畫面中的列會保持空白的問題
  • 修正未登入時 claude remote-control --help 不會印出使用說明就直接結束的問題
  • 修正 /design consent 和 /design revoke 在雲端工作階段中失敗時會建議使用 /design-login，但那裡並沒有這個功能；訊息現在改為指向 claude.ai/design/settings
  • 修正當 MCP server 協商出協定版本 2026-07-28 但省略 resultType、ttlMs 或 cacheScope 時，會導致 server 顯示沒有工具、或每次工具呼叫都失敗的問題
  • 修正提示建議（prompt suggestions）會消耗你方案只能用 credit 付費的模型的用量：現在在一則回覆以 credit 計費後就會略過
  • 修正用反引號包起來的 URL 換行時只有第一行可以點擊的問題；在支援超連結的終端機中，現在整段 URL 會是一條連結
  • 修正當找不到 plugin 時，claude plugin details <name>@builtin 會建議 claude plugin list（但它從來不會顯示內建 plugin）的問題；現在改為指向 /plugin
  • 修正連結開頭的 emoji 換行時會多寬一欄的問題，這會讓它在問題預覽中被隱藏，並把表格變成清單
  • 修正在 git 2.56 以上版本中，當有一個殘留的 .git 檔指向不存在的目錄時，worktree 隔離會拒絕建立或恢復 worktree 的問題
  • 修正雲端工作階段在新 process 中恢復後，成本和用量會從零重新開始計算的問題
  • Self-hosted runner：修正在重複使用以 git reftable 格式儲存的 checkout 的工作階段中，git fetch 會以「bad object refs/heads」失敗的問題
  • Windows：修正在 exFAT 或 FAT32 磁碟機上的專案，每次檔案寫入都會被拒絕或跳出詢問的問題，包含用 --plugin-dir 啟動的工作階段
  • 改善啟用大量 plugin 時的啟動時間：plugin 的指令和 agent 檔案現在載入所需的檔案系統呼叫大幅減少，在 Windows 上尤其明顯
  • 改善使用伺服器端分類器的 auto mode：太長而無法通過安全檢查的對話現在會被壓縮，而不是每個被檢查的工具呼叫都被拒絕
  • 改善背景工作階段從其他資料夾重新開啟但沒有 LLM gateway 時顯示的訊息：現在會說明原因，而不是顯示「Not logged in」
  • 變更 claude -p 和沒有權限模式的 Agent SDK 工作階段，在第三方供應商上、關閉遙測或全新安裝時，改為以 default 模式啟動；--permission-mode auto 仍維持 auto
  • 變更 fork subagent（subagent_type: "fork"）在 claude -p、Agent SDK、桌面版 app 和 VS Code 中預設開啟，就像在終端機中那樣；CLAUDE_CODE_FORK_SUBAGENT=0 可以關掉它，而 claude mcp serve 一律不提供
  • 變更桌面版 app 和 VS Code，讓主對話的 subagent 一律在背景執行（就像終端機那樣），而不是讓 Claude 自行決定；在 claude -p、Agent SDK、桌面版 app 和 VS Code 中，subagent 自己的 Agent 呼叫現在預設在前景執行
  • 變更 ← for agents 頁尾提示，在工作階段開啟 10 秒後隱藏；等待你處理的 agent 數量仍會顯示
  • 變更 Claude in Chrome 說明在系統提示（system prompt）中的位置，讓新對話可以從共用的 prompt cache 讀取它們
  • 變更 prompt 和 agent hook，讓同一事件最多同時執行 12 個；其餘的要排隊等候

  • [VSCode] 修正從面板登入 MCP server 時，若 server URL 含有查詢字串（query string）會開啟一個壞掉的授權頁面的問題
