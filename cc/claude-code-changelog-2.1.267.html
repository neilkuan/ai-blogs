Claude Code 2.1.267 更新日誌

翻譯自 官方 CHANGELOG

2.1.267

  • 新增 maxEffortLevel 設定（可放在頂層，或在 modelSettings 底下針對個別模型設定）：能為每個 provider 設定 effort level 上限，包含 Bedrock、Vertex 和 Foundry；使用者仍然可以選擇更低的等級
  • 新增 --system-prompt-snapshot off，讓每次請求都重新產生 system prompt，而不是重複使用對話中記錄的 prompt（方便反覆調整 prompt 文字）
  • 修正 Cowork 雲端排程任務在啟動時失敗的問題，這會發生在受管理設定（managed settings）要求 sandbox 的組織上
  • 修正 /context 和其他本地指令的輸出在行動裝置 client 上顯示空白的問題
  • 修正在 agent view 中重新連上 tmux 或 ssh session 後，shift+enter 和 option+backspace 失效的問題
  • 修正在全螢幕模式往上捲動時，最上方那個暗色的 last-prompt 標題沒有出現的問題
  • 修正 Workflow 的 agent() 呼叫在 auto 模式下，因輸出 schema 過大而直接被拒絕、而非交給安全分類器（safety classifier）檢查的問題
  • 修正一個 marketplace 項目路徑若包含反斜線，可能在 macOS 和 Linux 上繞過對已抓取 marketplace 的隔離檢查（containment check）的問題
  • 修正在 Claude Desktop 之類的宿主 app 底下，AWS 或 Google Cloud 憑證逾期時，會先重試十次並顯示籠統的「request failed」，之後才跳出重新驗證錯誤的問題
  • 修正透過 -p --resume 執行 /compact 或其他斜線指令後恢復 session 的問題：不再插入多餘的「Continue from where you left off.」這一輪對話
  • 修正恢復大型 session（transcript 超過 5 MB）時的問題：平行工具呼叫及其 hook 輸出不再從重新載入的對話中被遺漏
  • 修正受管理的 allowedHttpHookUrls、httpHookAllowedEnvVars 和 allowedChannelPlugins 在無法讀取時的行為：現在會全部拒絕、而不是全部放行
  • 修正在受管理設定要求使用 Claude apps gateway 登入的機器上執行 /login 的問題：現在按 Esc 會關閉對話框，而不是毫無反應
  • 修正 artifact 發佈在上傳途中連線中斷而被截斷的問題：現在只要 Claude Code 能判斷上傳從未完成，就會重試一次，而不是回報未知結果
  • 修正自訂指令、skill 和 subagent 上的 effort: frontmatter，在預設 effort 仍被固定住的模型（Opus 4.7、Opus 4.8、Fable 5）上被忽略的問題
  • 修正 artifact 發佈在頁面檔案不是有效 UTF-8、或含有替代字元（U+FFFD）時，出現無用錯誤訊息的問題；現在錯誤會指出要修正的行號和欄位
  • 修正 claude agents 的 @ 目錄選單，沒有列出 session 開始後才建立的 repository 的問題
  • 修正加入 Claude Desktop 或 VS Code session 的 Remote Control client，會顯示過時的權限模式、直到再次變更為止的問題

  • 修正在一個 session 內，不同模型或模式的請求回報不同限制時段時，用量限制警告會一閃一閃的問題
  • 修正當 MCP 伺服器重新送出、或內建工具重新渲染一個模型已載入的工具時，先前的 reasoning 被丟棄的問題
  • 修正某個工具在對話進行中消失（來自已斷線的 MCP 伺服器或升級）會重寫工具清單、並丟棄先前 thinking 的問題
  • 修正從對話 fork 出來的背景 worker，在 session 進行中把 EnterWorktree 加進對話的工具區塊，導致 prompt-cache 無法重用的問題
